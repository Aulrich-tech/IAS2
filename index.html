System Integration vs. System Architecture

System Integration

The process of combining all virtual and physical components into a single, cohesive infrastructure.

  • Virtual components — data recorded in software, applications, and databases.
  • Physical components — computer hardware modules.

System Architecture

The architectural model of a system, responsible for defining the system's behavior. It's the arrangement of components, their relationships, and how they interact to attain the system's goals.

It lets new applications use existing resources with minimal interruption.

System Integration

  • A process
  • Deals with software, hardware, and data
  • Produces a working, connected environment
vs

System Architecture

  • A design
  • Components and their relationships
  • A blueprint for building the connections

6 Methods of Integration

Point to Point

Direct connection between 2 system components.

Star

5 systems require 10 connections. Enables enhanced functionality, but is sensible only with a limited number of subsystems.

Hub and Spoke

5 connections instead of ten. The hub decouples data senders from receivers, significantly simplifying sustainability and security.

Vertical Integration

Straightforward and uncomplicated with few systems. Ideal for basic, single-function integrations — but any new functionality requires its own silo.

Horizontal Integration

One line per subsystem, all feeding into one common layer. All subsystems communicate through that layer. (Covered properly in Module 6.)

Common Data Format

Removes the need for an adapter per subsystem — they communicate seamlessly. Fairly complex, and requires extensive coding knowledge.

Advantages & Challenges of System Integration

Advantages

  • Consolidates and streamlines all correlated data
  • Improves data accessibility
  • Eliminates repetitive manual data entry
  • Centralized storage removes duplicate stores and their cost
↔

Challenges

  • Systems are genuinely hard to integrate
  • Variety of tools on the market makes choosing difficult
  • Integrating diverse systems is complex and time-consuming
  • Can simply be too expensive for many enterprises

Role in Modern Organizations — The System Integrator

The System Integrator

Specialized in bringing together disparate internal and external applications, combining multiple subsystems into a singular, integrated solution.

These roles exist at every large Philippine bank, telco, and BPO.

Payoff

Streamlined, real-time data sharing and increased efficiency.

5 Key Principles

Loose Coupling1

Designing systems with minimal interdependencies. Enables adaptability and makes it simpler to modify.

Service-Oriented Architecture2

Autonomous, loosely coupled services with well-defined interfaces.

Data Integration and Transformation3

Merging and consolidating data from many sources.

Scalability and Performance4

Handling growing data, traffic, and transactions while still meeting response-time expectations.

Security and Governance5

Authentication, authorization, data protection, and access control — for availability, confidentiality, and integrity.

9 Patterns and Styles

Point to Point

Systems linked one to one.

Hub and Spoke

A central hub brokers between spokes.

Publish / Subscribe

Publishers publish to topics.

Service-Oriented Architecture

Reusable services with clear interfaces.

Enterprise Service Bus

Centralized message backbone that mediates.

Event-Driven Architecture

Components emit events.

Microservices

App split into small, independent services.

Batch Processing

Data collected over a period, then processed.

Message-Oriented Middleware

Asynchronous messaging that decouples sender and receiver.
